**Статус:** решение принято, этапы 1–2 реализованы, этап 3 отменён заказчиком
**Дата:** 25.10.2026 (обновлено после ответа заказчика)

**Ветка:** `develop` (+ PR #1 с README уже влит)

## 0. Короткий ответ заказчику (можно отправить как есть)

> Нужна фича **«Трохоидальная обработка по Z-уровням»**: в КОМПАС-3D V19 выбираешь контур/карман, задаёшь параметры (диаметр фрезы D, шаг трохоиды Ae, шаг по глубине ΔZ, обороты S, подача F, припуск), нажимаешь кнопку — и получаешь готовую управляющую программу G-код с послойными трохоидальными проходами, которую можно сразу проверить в 3D-симуляторе.
>
> Изначально хотели сделать именно кнопку **внутри** панели инструментов модуля «Фрезерная обработка» (перехват рабочей сессии КОМПАС). Но этот путь упёрся в лицензию: без лицензионной версии с модулем ЧПУ его внутренний API недоступен, поэтому внедриться в панель не получается. Поэтому идея трансформировалась: делать **отдельное приложение-спутник**, которое подключается к уже запущенному КОМПАС-3D через внешний COM API 7, забирает геометрию и генерирует G-код само. Такой прототип уже есть — нужно сначала привести в порядок то, что работает «кривовато», а затем добавить саму стратегию по Z-уровням.
>
> Нам от вас нужны три вещи: (1) решение — ждём лицензионный КОМПАС-3D V19 с модулем ЧПУ и SDK или соглашаемся на автономный режим; (2) тестовая деталь `.m3d` с нужным контуром и требуемой глубиной; (3) стойка/станок, под который нужен постпроцессор (LinuxCNC, HAAS, Fanuc, Siemens).

## 2. Исходная идея и почему она трансформировалась

**Исходная формулировка (из переписки):**
> «Доделать перехват рабочей сессии Компас 3D V19 и его модуля ЧПУ "Фрезерная обработка", чтобы на панели инструментов появилась кнопка "Трохоидальная обработка по Z-уровням" и можно было сгенерировать G-код под этот вид стратегии».

Здесь важно разделить **два разных уровня интеграции**, которые в разговоре смешались:

| Уровень | Что это | Состояние в проекте |
| --- | --- | --- |
| **A. Внешнее COM-подключение** | Приложение цепляется к уже запущенному КОМПАС-3D через `GetActiveObject` / API 7 и читает активный документ | ✅ Реализовано в `Services/KompasService.cs` — приложение получает `ActiveDocument`, имя детали и точки внешнего контура выделенной плоской грани |
| **B. Внутреннее дополнение (in-process add-in)** | DLL-библиотека внутри модуля «Фрезерная обработка»: своя кнопка на его панели, доступ к дереву операций, стратегиям и встроенному постпроцессору | ❌ Не работает в имеющемся окружении: по наблюдению разработчика, нелицензионная версия «закрывает» API модуля ЧПУ |

То есть «перехват сессии» на уровне **A** уже есть. Недоступен именно уровень **B** — встраивание в панель инструментов CAM-модуля. Утверждение о том, что причина в лицензии, пока **гипотеза разработчика**; её надо проверить (см. [§7](#7-риски-и-открытые-вопросы)), но для планирования работ важно, что без подтверждённого доступа к SDK модуля ЧПУ уровень B не реализуем.

**Трансформированная идея:** не зависеть от внутреннего API CAM-модуля, а сделать законченный внешний инструмент, который решает ту же прикладную задачу — послойную трохоидальную обработку с выдачей G-кода. Кнопка «Трохоидальная обработка по Z-уровням» при этом живёт в окне нашего приложения. Если позже появится лицензионный КОМПАС-3D V19 + SDK, тот же движок можно будет «приземлить» в панель модуля ЧПУ как надстройку (режим B) — архитектурно движок генерации от UI уже отделён.

## 3. Формулировка фичи

> **«Трохоидальная обработка по Z-уровням»** — стратегия черновой/получистовой выборки материала, при которой инструмент на каждом уровне глубины `Z_k` движется по трохоидальным петлям (полные окружности `G2`/`G3` радиуса `D/2` с шагом `Ae` вдоль контура), а уровни проходятся сверху вниз с шагом `ΔZ`. На выходе — управляющая программа в G-коде под выбранный постпроцессор и её покадровая 3D-визуализация со снятием материала.

**Пользовательский сценарий (режим B — целевой):**
1. В КОМПАС-3D V19 открыта деталь, выбран контур/карман в модуле «Фрезерная обработка».
2. На панели инструментов нажата кнопка **«Трохоидальная обработка по Z-уровням»**.
3. Открывается форма параметров: `D`, `Ae`, `ΔZ`, `Z_верх`, `Z_низ`, припуск, `S`, `F`, безопасная высота, направление обхода, постпроцессор.
4. Нажатие «Сформировать УП» → G-код + окно симуляции.

**Пользовательский сценарий (режим A — доступен сейчас, без лицензии CAM-модуля):**
1. Запущен КОМПАС-3D с открытой деталью; в нашем приложении нажато «Подключиться к КОМПАС».
2. Выделена плоская грань (или используется демо-контур).
3. Те же параметры в главном окне → «Сформировать УП».
4. G-код записывается в файл и открывается в 3D-симуляторе.

Разница только в том, **откуда** приходит кнопка и геометрия. Поэтому режим A — не «урезанная версия», а первый этап того же продукта.

### Этап 2. Стратегия «Трохоидальная обработка по Z-уровням»

Новый слой над `TrochoidEngine` (например, `Services/ZLevelTrochoidStrategy.cs`):

**Входные параметры:**

| Параметр | Смысл | Ориентир |
| --- | --- | --- |
| `D` | Диаметр фрезы | 10 мм |
| `Ae` | Шаг трохоиды (продольная подача центра петли) | 1 мм |
| `ΔZ` | Шаг по глубине между уровнями | 2 мм |
| `Z_top`, `Z_bottom` | Верх и низ обработки | 0 / −10 мм |
| `Allowance` | Припуск на стенку/дно | 0.2 мм |
| `S`, `F` | Обороты и подача | 6000 / 400 |
| `SafeZ` | Безопасная высота перехода | 50 мм |
| `Direction` | Попутное/встречное, обход контура | — |
| `Postprocessor` | Стойка | LinuxCNC / HAAS |

**Алгоритм:**

```
1. Контур → смещённая траектория центра инструмента (D/2 + припуск).
2. Для каждого уровня Z_k = Z_top - k·ΔZ, пока Z_k ≥ Z_bottom:
     a. безопасный подвод: G0 Z SafeZ → G0 X/Y старта → G1 Z_k F(врезания);
     b. трохоидальные петли вдоль контура с шагом Ae (существующий TrochoidEngine,
        но с параметром Z_k и с дугами G2/G3 по направлению);
     c. при необходимости — дополнительные проходы внутрь (offset-петли для кармана);
     d. отвод на SafeZ, переход к следующему уровню (без «протяжек» сквозь материал).
3. Склейка кадров, шапка/финал, применение постпроцессора, запись файла.
4. Передача текста в симулятор.
```

**Требования к результату:**
- корректные `I/J` для каждой дуги, отсутствие самопересечений и «прыжков» между уровнями;
- постоянная толщина стружки (Ae не меняется) и плавное движение приводов;
- симулятор показывает съём материала **на каждом уровне**, а не только на `Z0`;
- время обработки считается с учётом всех уровней и холостых переходов;
- программа открывается в симуляторе станка без ошибок парсинга.

### Этап 3. Интеграция в КОМПАС-3D V19 (только при наличии лицензии и SDK)

- DLL-дополнение (add-in) для модуля «Фрезерная обработка», регистрирующее кнопку **«Трохоидальная обработка по Z-уровням»** на панели инструментов;
- кнопка вызывает тот же движок генерации (общая библиотека `Services`), передаёт выбранную операцию/контур и получает G-код;
- если SDK модуля ЧПУ окажется недоступен — остаётся режим A (внешнее приложение) как основной, а кнопка реализуется через макрос/команду КОМПАС, запускающую наше приложение.

> ⚠️ Этап 3 **нельзя обещать заказчику без проверки** наличия лицензии, SDK и документированного API модуля ЧПУ. Это отдельная развилка (см. §6 и §7).

## 6. Что нужно от заказчика (блокирующие вопросы)

## 7. Риски и открытые вопросы

| Риск | Комментарий / что делать |
| --- | --- |
| Причина недоступности API — не только лицензия | Гипотеза «в нелицензионной версии API закрыт» требует проверки: сверить версию/сборку КОМПАС, наличие зарегистрированного CLSID `Kompas.Application.7`, доступность библиотеки типов модуля ЧПУ, возможность зарегистрировать in-process DLL. Возможны и другие причины: отсутствие SDK, другой разрядность процесса, UAC/права, не тот профиль пользователя, COM-сервер под другим пользователем |
| Внутренний API CAM-модуля может не документироваться | Уточнить у АСКОН/поставщика, есть ли открытый SDK для модуля «Фрезерная обработка» V19 и лицензия разработчика. Без этого этап 3 невыполним |
| Внешний COM API 7 даёт только геометрию, не стратегию | Это нормально: стратегия реализуется в нашем коде. Но дерево операций, припуски и параметры заготовки из CAM-модуля придётся задавать в своей форме |
| Нет среды для проверки | В текущем окружении нет .NET 10 SDK и КОМПАС-3D: код пишется, но собирается/проверяется на машине разработчика с Windows. Нужны скриншоты/логи и тестовый прогон |
| Точность трохоиды на реальном станке | Полные окружности `G2` с относительными `I/J` поддерживаются не всеми стойками; для HAAS/Fanuc может потребоваться разбиение на дуги ≤ 180° или `G3`. Проверить на симуляторе стойки |
| NDA/лицензионные ограничения | Перед передачей логов, моделей и SDK третьим лицам уточнить условия у заказчика |

## 8. Критерии приёмки фичи

1. Пользователь задаёт параметры `D/Ae/ΔZ/Z_top/Z_bottom/припуск/S/F` и получает УП с послойными трохоидальными проходами.
2. G-код проходит проверку в симуляторе стойки: нет ошибок парсинга, нет врезаний на холостых переходах, `Z` каждого уровня соответствует `ΔZ`.
3. Симулятор проекта показывает съём материала на всех уровнях; оценка времени учитывает все проходы.
4. Кнопка запуска доступна: в автономном приложении — обязательно; в панели модуля ЧПУ КОМПАС-3D V19 — при наличии лицензии и SDK.
5. Все исправления этапа 1 с приоритетом P0 закрыты; на русской локали программа генерируется корректно.
6. Есть модульные тесты на генерацию петель, склейку уровней и парсинг дуг.

## 9. Порядок работ

```
Этап 1 (P0-правки) ──▶ Этап 1 (P1-правки) ──▶ Этап 2 (Z-уровни) ──▶ проверка на стенде
                                                        │
                                                        └──▶ Этап 3 — ОТМЕНЁН заказчиком 25.10.2026
```

Этап 3 (кнопка внутри КОМПАС) снят с плана. Движок генерации остаётся отделённым от UI, поэтому при появлении лицензионного SDK модуля ЧПУ его можно будет переиспользовать без переписывания.

## 10. Термины

- **Ae** — шаг трохоиды, смещение центра петли вдоль контура; определяет толщину стружки.
- **ΔZ** — шаг по глубине между уровнями обработки.
- **Трохоида** — траектория из последовательных круговых петель, позволяющая фрезеровать паз на полную ширину при малой радиальной нагрузке.
- **G2/G3** — круговая интерполяция по/против часовой стрелки; `I/J` — относительные координаты центра дуги.
- **API 7** — внешний COM-интерфейс КОМПАС-3D (`IApplication`), используемый в проекте.
- **In-process add-in** — DLL-библиотека, загружаемая внутрь процесса КОМПАС-3D; требуется для кнопки в панели CAM-модуля.
- **Постпроцессор** — преобразователь обобщённой траектории в G-код конкретной стойки.
